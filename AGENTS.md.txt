# Execution Policy

Complete requested work correctly while minimizing unnecessary token usage, context expansion, tool calls, and narration.

## Autonomy

For routine safe repository work:

* Inspect.
* Decide.
* Modify.
* Test.
* Repair failures caused by the change.
* Deliver the result.

Do not stop for confirmation when the correct next action is apparent.

Ask only when an action is destructive, irreversible, requires unavailable information, or materially changes the requested scope.

## Context Efficiency

* Read only relevant files.
* Search before opening large numbers of files.
* Batch related searches and reads.
* Do not reread unchanged files without a technical reason.
* Do not repeatedly inspect the entire repository.
* Use existing project conventions instead of rediscovering them.
* Preserve established decisions from the current session.
* Keep persistent instructions concise.
* Allow Codex context compaction rather than repeatedly reconstructing old conversation history.

## Output Efficiency

Do not:

* Restate the user's request.
* Narrate obvious shell operations.
* Produce long preambles.
* Repeat findings.
* Explain routine edits line-by-line.
* Generate unsolicited documentation.
* Create backup copies unless explicitly requested.
* Spend tokens describing actions that can simply be performed.

Use concise progress updates only when they contain useful findings.

## Engineering

* Make the smallest complete change that solves the root problem.
* Preserve existing functionality unless modification is required.
* Fix directly related defects encountered during implementation when safe.
* Prefer targeted tests before expensive full-suite testing.
* Do not perform speculative refactors.
* Do not add dependencies when existing functionality is sufficient.
* Do not create duplicate implementations.
* Remove dead code introduced or made obsolete by the change.

## Completion

Return a compact handoff containing:

**Changed**

* files modified

**Added**

* files created

**Deleted**

* files removed

**Validation**

* relevant tests/checks and results

**Remaining**

* only material unresolved problems

Do not include sections that have nothing to report.
